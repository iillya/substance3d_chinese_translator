# 纯显示分支与 Main 的功能对照

日期：2026-09-25。分支：`pure-display-layer-experiment`。
对照基线：本地 `main`（`1bb0d4b`）。这是实验验收记录，不代表全部宿主版本已通过验收。

## 显示层边界

宿主控件、模型、标签页业务数据保留原文。翻译发生于 QPainter 调用参数、只供绘制与测量使用的代理索引、插件自己创建的预览文档。
当前实现不安装全局 QTranslator，以保留 Painter 官方中文的优先级；这属于当前架构选择，不是纯显示层一律禁止 QTranslator。边界以是否改变工程、模型、参数、内部查找或导出数据为准，字体度量和显示缓存可以适配中文。
现有绘制与委托路径不写回 QAction、QLabel、QComboBox、输入框或资源模型的中文文本。
输入保护依据当前绘制对象的真实 Qt 类型及父链；激活一个输入框不会令其他标签恢复英文。空输入框的占位提示允许翻译。

2026-09-29 复核：修复 Designer 节点绘制在精确词典查询前跳过含中文标题的问题。显式中文与中英混合标题映射现可显示，未配置映射的中文仍保留原样；真实 Qt5/Qt6 像素测试同时验证源标题不变及关闭后还原。Qt5、Qt6、提取器 3 项 CTest 和 42 项 Python 测试通过；双版本 DLL、提取器及正式 ZIP 已重建。未以这些离屏测试代替 Adobe 宿主实机验收。

## 本轮消除的问题

- 通用绘制曾硬编码 Qt6，导致 Qt5 构建没有通用挂载；现在每个 DLL 只按自身编译 Qt 主版本解析导出。
- 删除每次省略文本绘制时遍历全词典并随意选择最短前缀的逻辑。
- 委托已安装时不再请求下一次重绘，避免重复 Paint 形成刷新循环。
- 绘制事件中的下拉归属查找改为父链查找；异常脱离父链的弹窗在非绘制扫描中安装。
- EnumProcessModules 返回超出缓冲区容量时限制访问数量，防止数组越界。
- 删除旧的原文属性、下拉自定义角色和 tabData 还原路径，避免误把宿主业务数据当原文。
- 原文提示窗口不再经过通用翻译，避免英文提示被重新翻成中文。

## 自动测试

```powershell
cmake -S source/cpp -B source/cpp/build-display -A x64 -DSP_BUILD_EXTRACTOR=OFF -DSP_BUILD_DISPLAY_TESTS=ON
cmake --build source/cpp/build-display --config Release --parallel 4
ctest --test-dir source/cpp/build-display -C Release --output-on-failure
python -m unittest discover -s source/tests -q
```

MSVC `/W4 /WX` 下同时编译 Qt 5.12.5 和 Qt 6.5.3 DLL。
两个离屏测试程序均通过，包含真实 IAT 挂载、原生控件绘制、开关和卸载，不依赖鼠标或桌面操作。
Qt5 离屏平台需要 `QT_QPA_FONTDIR`；测试环境已指向 Windows 字体目录，防止英文和中文都渲染为空白而误判。

## 交付与限制

实验包：`dist/substance3d_chinese_translator-pure-display.zip`。两个翻译 DLL 为本轮重新编译产物；提取器保留现有二进制，源码未变。
本次审核没有部署、启动或操作 Painter/Designer。未提交、未合并 Main。
完整修复、兼容性和性能记录见 [PURE_DISPLAY_AUDIT.md](PURE_DISPLAY_AUDIT.md)。

当前共享 Qt SDK 可用于编译翻译模块；旧分支删除了 `sdks/deps` 中的提取器依赖，完整重新编译提取器仍需通过 `SP_DEPS_ROOT` 提供这些库。
`SP_BUILD_EXTRACTOR=OFF` 仅用于显示模块构建，不冒充提取器已重新编译。

仍须实际验收：Painter 主资源库与资源选择器中文搜索、资源预览图片及元数据、图层命名/编辑/混合模式、Designer 资源库与节点端口、窄面板与高 DPI、中英文反复切换和卸载。
Qt 原生像素测试不能证明私有控件全部覆盖。绕过 QPainter 文本入口的自定义渲染、富文本交互几何和原生系统标题栏，仍需针对实际宿主检查；不以新增宽泛输入过滤或改写原文掩盖缺口。
