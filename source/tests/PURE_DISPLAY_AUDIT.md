## 性能实测

测试环境为当前 Windows 电脑、Release 构建、Microsoft YaHei 12、离屏 Qt。加载实际 15,689 条全局词典和 35 条控件规则；每种环境运行 3 次取中位数。查询每项循环 200,000 次；相同未命中文本的 QLabel 绘制各 4,000 次，防止中英文长度不同造成错误比较。

| 测量项 | Qt 5.12.5 | Qt 6.5.3 | Designer Qt 6.5.8 |
| --- | ---: | ---: | ---: |
| JSON 解析及建立原生查询表 | 25.65 ms | 25.41 ms | 26.16 ms |
| 精确查询 | 0.051 μs | 0.048 μs | 0.049 μs |
| 规范化查询批次（部分词也可能精确命中） | 0.840 μs | 0.717 μs | 0.802 μs |
| 未命中查询 | 0.995 μs | 1.253 μs | 1.173 μs |
| 原生 QLabel 完整绘制，无引擎 | 27.26 μs | 15.38 μs | 15.46 μs |
| 引擎挂载、翻译关闭 | 27.95 μs | 15.60 μs | 15.71 μs |
| 引擎挂载、翻译开启 | 30.39 μs | 18.52 μs | 18.40 μs |
| 词典加载前后进程私有内存增量 | 5.98 MiB | 5.54 MiB | 5.46 MiB |

普通标签在该样本中增加约 3 μs/次完整绘制。关闭状态的小幅波动属于测量噪声，不能宣称零开销或负开销。词典内存增量不是整个插件常驻内存，加载时间不包含 Python 解析与 ctypes 传递。上述结果也不是 SP/SD 整个进程的 CPU 占用率。

默认没有全量扫描定时唤醒；显示事件过滤器与转发挂钩仍然存在。中文搜索发生于输入、模型或词典变化，并由单次计时器合并处理，不是持续后台扫描。

### 剩余热点：Designer 节点所属对象查找

`graphOwnerItem()` 仍遍历场景图元并比较变换。Designer Qt 6.5.8 的模拟场景中，一次查询在 100 / 1000 / 5000 个图元时分别约 **3.03 / 36.51 / 247.23 μs**。它发生在启用节点翻译的绘制路径，密集节点图可能累积为明显开销。

本轮未把它替换成未经宿主验证的几何猜测或跨帧裸指针缓存。后续应单独实现绘制批次内的索引，并验证移动、缩放、删除节点及端口继承变换后再启用。该问题已测量并保留记录，不能用普通标签的低开销掩盖。

## 2026-09-25 第二轮性能审核

以下保留第一阶段的测量和当时结论；后续实施结果见文末“完整性能优化收尾”。

基线为已发布 v1.3.7（`882e0e0`）。下述优化仅在本地源码和测试构建中，未改变版本号、dist 安装包、GitHub 发布或已安装插件。引擎 API 仍为 15，测试构建标识为 `20260925-pure-display-performance-api15`。

### 本轮已改

1. `QRectF` 两种绘制入口在端口判断和标题翻译之间共享一次所属图元查询，最坏从两次场景遍历降为一次。结果只存活于一次 hook 内、转发 Qt 绘制之前，不跨帧保存裸指针。
2. 场景查询把视口变换移到循环外；找到零误差时立即结束。保留原场景顺序、相同变换时的第一项和非精确变换的最近项规则，没有更改匹配覆盖范围。`scene()->items()` 的枚举和排序成本依然存在。
3. 资源搜索仅在可见行集合改变时额外执行 `doItemsLayout()` 和更新请求。原生模型的排版、刷新仍由 Qt 自己处理；宿主原本隐藏的行继续保留。
4. `dataChanged` 仅报告缩略图、尺寸或提示变化时不再启动中文搜索。空角色列表、显示文本、编辑值以及未知宿主角色仍重新筛选，避免漏掉实际内容变化。

### 同机前后对照

Release 离屏测试，每种运行库各 3 次取中位数。节点样本包含 5,000 个图元，同一未命中文字经真实 `QRectF/Align` hook 完整绘制 100 次；分别把所属项放在遍历顺序首尾。这样不会把提前返回的最好情况当成普遍结果。

资源样本使用具名 Qt 资源面板替身和 5,000 行标准模型，先应用中文筛选，再重复执行 20 次相同筛选；计时不包含有意设置的 40 ms 防抖等待。模型变化和真实 Adobe 数据库的耗时不包含在该样本内。

| 测量项（修改前 → 修改后） | Qt 5.12.5 | Qt 6.5.3 | Designer Qt 6.5.8 |
| --- | ---: | ---: | ---: |
| 5,000 图元、所属项最后，单次完整文字绘制 | 484.09 → 238.46 μs | 520.67 → 246.51 μs | 524.65 → 244.36 μs |
| 5,000 图元、所属项最前，单次完整文字绘制 | 487.58 → 183.78 μs | 495.34 → 181.05 μs | 500.84 → 182.98 μs |
| 5,000 资源、相同筛选结果，单次筛选 | 15.32 → 9.83 ms | 16.10 → 9.43 ms | 14.95 → 8.69 ms |
| 20 次相同筛选额外排版次数 | 20 → 0 | 20 → 0 | 20 → 0 |
| 普通 QLabel 完整绘制，翻译开启 | 31.23 → 29.77 μs | 18.47 → 18.06 μs | 18.01 → 17.98 μs |

节点样本耗时降低约 51%–64%，重复筛选降低约 36%–42%。普通标签、词典加载和内存数据没有显示有意义的退化；标签的小幅改善包含测量噪声，不能将其宣传为稳定加速。本轮没有新增长期缓存，词典加载后的私有内存增量仍约 5.4–6.0 MiB；这是原生词典增量，并非整个插件（包含 Python）的内存占用。

以上都不是 SP/SD 整个进程的 CPU 占用率或真实项目帧率。未启动、操控或采样 Adobe 主程序。

## 2026-09-25 完整性能优化收尾

本节记录当前最终状态，取代上文尚未实施的优化清单。插件版本仍为 1.3.7，原生 API 升为 16，构建标识 `20260925-complete-performance-api16`；Python 与两个 DLL 必须成套使用。此次没有提交、发布、部署或启动 Adobe 主程序。

### 已完成的改动

- **节点绘制**：通过可选的公开 Qt `QPainter` 构造、析构、begin、end 导入挂钩划定一次绘制的有效期。前四次归属查询沿用原算法，第五次建立变换索引，避免只绘制少量标签时提前扫描整个大场景。缓存仅存标题、矩形、变换等值，不持有 `QGraphicsItem*`。保留同变换第一项、非精确变换最近项规则；场景变更、视口变换和嵌套事件会使索引失效，绘制结束即释放。不支持生命周期挂钩或超过容量时回退到原算法。
- **资源搜索**：按模型、控件作用域和词典版本缓存规范化搜索文本。文本角色改变时局部失效，插入、删除、重排、重置、更换模型和词典修改时重建；解绑或关闭筛选时释放。预热后重复筛选不再逐行读取 DisplayRole。原生隐藏行、业务模型、选择和输入保护保持原逻辑。
- **词条查询**：增加规范化缓存和包含控件作用域、助记符策略的查询结果缓存，也缓存未命中。保留无作用域的精确命中快速路径；词典编辑、替换和匹配开关变化统一失效。UTF-16 汉字判断不再分配临时 UTF-32 数组。
- **界面发现**：合并资源面板祖先查询、下拉归属查询及批量控件发现、委托安装、重绘的重复遍历；启动前的词典同步不额外扫描尚未安装的引擎。默认全量扫描计时器仍关闭。
- **词典同步**：新增原子批量替换 API，一次 UTF-8 JSON 传输同时替换普通及控件词典，校验成功才交换。词条数组保留规范化冲突时的原始覆盖顺序，失败保留上一版；不再逐条 ctypes 调用/通知，也不在重载词典时重置用户的节点翻译开关。
- **在线更新**：发布信息查询移到后台线程；查询和下载只在操作期间使用有父对象的计时器。取消或宿主退出不在 UI 线程 join 网络线程；后台线程不操作 Qt，临时下载文件在写入结束后清理。
- **提取器**：复用字段正则，GLSL 扫描先检查文件大小，将不平衡花括号的反复尾部扫描改为一次配对及有界恢复；已知 shader 扩展名直接进入元数据解析，避免 libarchive 把 shader 文本误识别为 mtree。去掉 Python UI 线程重复的目录枚举，由独立提取进程统一处理。

### 容量与适用边界

规范化与查询结果缓存分别有 1 MiB、2 MiB 的计费上限，计费包含文本和固定条目估算，并非精确的进程内存上限。单个资源筛选器最多缓存 20,000 行、4 MiB UTF-16 文本，另有容器和字符串对象开销；超出部分实时处理。节点批次最多 30,000 个图元、4 MiB 标题文本，最多 8 个同时活动批次；另有索引和元数据开销，超限回退原查询。这些容量用于限制增长，并非宣称整个插件只占上述内存。

节点数据仅在当前绘制批次复用，不跨帧持有图元指针；宿主在同一 paint 内、未触发事件直接修改私有元数据的特殊行为仍需实机检查。公开 Qt 导入挂钩也有开销，当前算法与测试不能证明任意 Adobe 私有控件或第三方挂钩都兼容。
